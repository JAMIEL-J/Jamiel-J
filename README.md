
## Fraud Detection

Built a fraud classification pipeline where **missing fraudulent transactions matters more than maximizing generic accuracy**.

The workflow included:

* Data preprocessing
* Class imbalance handling
* SMOTE
* LightGBM modelling
* Feature analysis
* Probability calibration
* Threshold optimization
* Recall-focused evaluation

### Result

**99.76% recall**

**0.9993 ROC-AUC**

The classification threshold was tuned around the cost of missed fraud rather than simply maximizing accuracy.

# My Approach

I don't start with:

```text
"What technology should I use?"
```

I start with:

```text
"What decision are we trying to make?"
```

Then work backwards:

```text
Question
   ↓
Data
   ↓
Validation
   ↓
Analysis
   ↓
Evidence
   ↓
Decision
```

That's why my projects often sit between **analytics and engineering**.

I want the analysis to be reproducible, the numbers to be defensible, and the final output to be useful to someone making a decision.
